# 前端 MainUI.html

## 连接与通讯

### 初始化与建立连接

MainUI.html 在加载布局模块和功能模块之前定义五组回调列表。模块通过注册
回调参与初始化、连接状态处理和消息处理：

| 回调列表 | 参数 | 调用时机 |
| --- | --- | --- |
| `onload_func_list` | 无 | 页面加载完成后、建立连接前 |
| `when_connect_func_list` | 无 | WebSocket 连接成功时 |
| `when_disconnect_func_list` | 无 | WebSocket 关闭时 |
| `message_proc_func_list` | `data` | 收到并解析 JSON 文本消息后 |
| `binary_message_proc_func_list` | `header, payload` | 收到并解析 HSV1 二进制消息后 |

`window.onload` 按注册顺序调用初始化回调，然后初始化服务器地址控件，恢复
上一次输入的地址并自动连接；没有记录时使用 `localhost:8768`。
根目录右侧的输入框接受 IP、主机名及端口（IPv6 使用方括号），省略端口时
使用 8768；也接受 HTTP/HTTPS、WS/WSS 地址，WebSocket 路径统一为 `/ws`。
HTTPS 页面只允许连接加密地址。客户端须填写服务端实际配置的端口。
`createAutoReconnectWebSocket(url, onMessage)` 创建原生 WebSocket，并将
`binaryType` 设为 `arraybuffer`。

连接成功时，框架先设置内部连接状态，再通过 `BasicEvent.when_connect()`
更新状态文字、启用根目录输入框，随后调用连接回调。各列表按数组顺序同步
调用回调，单个回调同步抛出的异常会被记录，不阻止后续回调执行；框架不等待
前端回调返回的 Promise。

### socket 接口与发送消息

全局变量 `socket` 保存连接管理器对象，初始为 `null`：

| 接口 | 行为 |
| --- | --- |
| `url` | 连接管理器的目标 WebSocket 地址，调用方应只读使用 |
| `send(data)` | 原生 WebSocket 处于 OPEN 时发送并返回 true，否则返回 false |
| `close()` | 关闭当前原生 WebSocket，并取消重连及连接超时定时器 |
| `reconnect()` | 立即尝试建立连接 |
| `isConnected()` | 返回内部连接状态 |
| `isActive()` | 当前管理器是否仍是页面使用的连接且未被主动停止 |

模块发送 JSON 命令时自行调用 `JSON.stringify()`，`send()` 不自动序列化，
也不缓存断线期间的消息。返回 true 表示已交给原生 WebSocket 发送，不表示
后端业务处理成功。

### 接收与分发消息

`messageProc(event)` 根据消息类型进行处理：

1. 文本消息通过 `JSON.parse()` 解析。如果 `command` 为 `SET_NOWPATH`，
   先用 `data.path` 更新根目录输入框，再把同一个 data 对象交给文本回调列表。
2. 二进制消息接受 ArrayBuffer 或 Blob；Blob 先转为 ArrayBuffer，再检查
   HSV1 魔数及 JSON 信息头长度。消息结构为：

   ```text
   4 字节魔数 0x48535631 | 4 字节无符号信息头长度（大端） | UTF-8 JSON 信息头 | 二进制载荷
   ```

   信息头解析为 header 对象，其余字节作为 payload（ArrayBuffer），依次
   传给二进制回调列表。

无法解析或结构错误的消息会被记录并丢弃。框架负责分发，模块自行检查
command、widgetId、streamId 等业务字段，判断消息是否属于自己。
同一连接的消息解析按到达顺序串行执行；关闭、重连或切换地址后，旧连接
事件及尚未完成的 Blob 解析结果不会再分发到模块。

### 地址历史与可用状态

合法输入、连接尝试和历史选择会写入浏览器 localStorage 的
`tiphereth.server-addresses.v1`，保存最近地址和最多 20 条去重历史。
刷新或重新打开页面恢复最近地址；记录属于当前浏览器，file:// 页面移动后
是否仍能访问原记录取决于浏览器。存储不可用时显示提示并退回内存记录。

输入框聚焦或点击箭头展开历史列表，每项最左侧显示状态圆点。列表打开时
通过各地址的 `/api/server-info` 检查协议版本及 `/ws` 路径；响应符合框架
协议时为绿色，请求失败或尚未确认时为红色，当前已建立的连接显示绿色。
每次最多并发探测 4 个地址，超时 2.5 秒，展开期间每 15 秒刷新；收起后
取消探测与刷新。圆点表示探测结果，不保证该地址的功能模块正常。
支持方向键选择、Enter 确认及 Escape 收起；选择历史只填入地址。

### 断线与自动重连

点击“连接”开始连接，按钮随即显示“断开”，连接中和等待重连时也可停止。
连接尝试超过 10 秒会关闭；意外断线后按 1、2、4、8、16、30 秒间隔重试，
后续保持 30 秒，成功后重置间隔。`onerror` 只记录错误，由 `onclose` 统一
安排重连。曾建立成功的连接断开时调用一次 `BasicEvent.when_disconnect()`，
清空并禁用根目录输入框，执行断线回调。重连成功再次执行连接回调。

点击“断开”调用 `disconnect()`，取消定时器、关闭连接并清空全局 socket，
主动断开不重连。切换地址建立连接前会先停止旧管理器，旧事件不能改变新连接。
页面离开时也会停止连接和历史探测。框架不更改第三方模块的业务状态归属。

### HTTP 资源地址接口

页面初始化完成后，布局模块和功能模块可以调用以下地址生成函数：

- `get_backend_http_url(path = '')`：从当前 socket 地址推导 HTTP/HTTPS 地址；
  空参数返回以 `/` 结尾的服务端基地址。禁止生成其他源的地址。
- `get_resource_url(rootId, relativePath)`：对资源根标识和相对路径分段编码，
  生成 `/resources/{rootId}/{relativePath}` 的绝对 HTTP 地址；反斜杠转换为
  路径分隔符，拒绝空路径、`.` 和 `..` 路径段。rootId 必须是非空字符串，
  且不能为 `.` 或 `..`。

这两个函数从 `socket.url` 推导地址，不执行请求，也不检查连接是否成功。
socket 为 null 时调用会报错。客户端可请求 `/api/server-info`，从响应的
`resource_roots` 数组获取资源根目录的 id，再传入 `get_resource_url()`。
模块收到后端提供的 `/resources/...` 相对 URL 时，使用
`get_backend_http_url(path)` 将其补全。HTTP 请求不携带凭据
（fetch 使用 `credentials: 'omit'`）。地址历史状态探测会请求服务信息。

# 后端 back.py

## 连接与通讯

### 启动与配置

要求 Python 3.10 或更新版本，使用 `requirements.txt` 中固定的 aiohttp 3.14.3。
主框架由 aiohttp 创建应用、监听端口并处理 WebSocket 连接。

启动时读取 `backend/config/global_config.json` 的 `base-port`：

- 缺少键时补写 `8768`；文件不存在时创建包含 `base_dir: ["./"]` 的默认配置。
- 端口必须是整数且在 1～65535 范围内，不接受布尔值或字符串。
- 配置补写采用同目录临时文件和原子替换，保留其他键及原有相对路径。
- JSON 错误、回写失败、监听失败会报错并以非零状态退出，不自动换端口。
- 监听 `0.0.0.0:<base-port>`，HTTP 和 `/ws` 共用此端口，不提供前端页面。

配置加载和模块初始化在启动时发生，单纯 import back 不产生这些副作用。

### HTTP 服务信息与资源访问

| 路由 | 方法 | 用途 |
| --- | --- | --- |
| `/api/server-info` | GET、HEAD、OPTIONS | 版本、协议版本、端口、能力和资源根目录列表 |
| `/resources/{rootId}/{relativePath}` | GET、HEAD、OPTIONS | 读取允许目录内的文件 |
| `/ws` | GET（WebSocket 升级） | 模块命令和二进制消息 |

服务信息返回 `version`、`protocol_version`（1）、`base_port`、
`websocket_path`（`/ws`）、`capabilities` 和 `resource_roots`。
capabilities 包含 http_resources、byte_ranges、websocket 三个布尔字段；
resource_roots 是 `[{"id": "root-...", "name": "目录名"}]`，不包含磁盘绝对路径。
服务信息使用 `Cache-Control: no-store`。

`ResourceRegistry` 在启动时登记有效的 base_dir 目录，将规范化绝对路径的
SHA-256 前 16 位映射为 `root-...` 标识。同一目录不因配置顺序变化而更换标识，
目录移动会产生新标识；标识仅用于定位，不是认证凭据。

资源请求只接受登记标识和相对路径。路径只解码一次，拒绝空段、`.`、`..`、
反斜杠、冒号、控制字符及以空格或点结尾的路径段，防止 Windows 路径别名和
备用数据流访问。最终路径经过 resolve 后必须仍在对应根目录内，符号链接
及 Windows 目录联接不能通向范围外。仅提供普通文件，不列出目录。
项目自身目录、运行后端目录和全局配置文件受到保护，即使 base_dir 配置了
其上级目录也不会通过资源接口发布。默认 base_dir 为 `./` 时指向后端目录，
不会登记成可下载资源根；需要在配置中指定实际的外部资源目录。

路径检查在线程中执行，文件响应使用 aiohttp `FileResponse`。它处理 HEAD、
单段 Range（起止范围、开放尾部、后缀范围）、206、416、ETag、Last-Modified
及条件请求。文件以有界缓冲传输，不整段载入内存；原生 sendfile 不可用时
由 aiohttp 回退至分块发送。字体和常见媒体类型明确指定 MIME，其余由 aiohttp
推断。文件使用 `Cache-Control: no-cache`，允许缓存但要求再次校验。
本接口不转码、不验证视频编码；播放支持取决于客户端及文件本身。

资源缺失、目录请求或未知 rootId 返回 404；非法路径或无权限返回 403；
不支持的方法返回 405。`/`、`/MainUI.html`、`/frontend/...` 均不注册。

只读 HTTP 接口允许无凭据跨源访问，`Access-Control-Allow-Origin` 为 `*`，
可供 file:// 页面使用。OPTIONS 接受 GET/HEAD，以及 Range、If-Range、
If-None-Match、If-Modified-Since 请求头；其他预检请求返回 403。
Content-Length、Content-Range、Accept-Ranges、ETag、Last-Modified 被暴露给
客户端。aiohttp 的 on_response_prepare 在发送响应头前添加这些字段，覆盖
文件响应在 prepare 时生成的 206/304/416 和 HTTP 错误响应。
不发送 Allow-Credentials，WebSocket 不走这套 CORS 流程。

### 模块接口与连接生命周期

`ModuleManager` 按 `backend/config/module_config.json` 中的配置顺序加载启用的
模块，通过 `create_module(global_config, back_version)` 创建实例；后端版本为
`TIPHERETH 1.0.0`。返回空值表示模块不支持该版本，此时跳过加载。

传给模块回调的 websocket 参数是 `backend/back.py` 中定义的
`FrameworkConnection`。每个客户端连接对应一个稳定对象，可用作模块自己的
字典键，并提供：

- `await send(str | bytes | bytearray | memoryview)`：发送一条消息，二进制不改写。
- `await close(code=1000, reason='')`：关闭该连接。
- `closed`：连接是否已关闭。
- `resource_url(file_path)`：将登记资源目录内的文件路径转换为
  `/resources/...` 相对 URL，应用同样的路径校验；不属于允许目录时抛出异常。
  该方法同步访问文件系统，耗时的网络盘调用可由模块放入工作线程执行。
- `recv()` 供框架唯一业务消费者使用，模块回调不得另外读取消息。

先发送 `SET_NOWPATH`，再按模块配置顺序调用 `when_connect(connection)`；
每条 JSON 对象按顺序调用 `message_proc(connection, data)`。上行消息须为
JSON 对象文本；下行 HSV1 由模块构造，适配层原样发送，前端负责解析和分发。

运行时的资源根目录相对于 backend 目录解析为绝对路径，不存在的路径记录
警告并跳过。有效路径通过 `SET_NOWPATH` 发送到前端，不回写这些绝对路径。

### 并发收发与连接限制

网络读取任务独立于业务分发任务，业务 await 时仍能处理 Ping/Pong、断线。
每连接最多排队 32 条上行消息，单条上限 1 MiB；超限或非法数据关闭该连接。
心跳参数为 30 秒，使用 aiohttp 的 Ping/Pong 与超时检测；关闭握手超时设为 5 秒。
发送使用每连接锁及 aiohttp 64 KiB 写缓冲水位（不是消息大小上限），等待锁
和发送合计超过 30 秒时关闭慢连接；适配层不另建无界输出队列。

不同连接具有各自的读取任务、分发任务、接收队列和发送锁；同一连接的消息
由单个业务消费者依次处理。模块实例由所有连接共享，框架不改变模块内部
状态的归属，也不替模块实现业务并发控制。模块中的同步阻塞操作仍会阻塞
共用的事件循环。

| 异常情况 | 关闭码 |
| --- | --- |
| 上行文本不是合法 JSON 对象 | 1007 |
| 上行消息为二进制 | 1003 |
| 上行消息超过大小限制 | 1009 |
| 接收队列已满或发送超时 | 1013 |
| 模块连接或消息回调发生未处理的普通异常（ConnectionError 除外） | 1011 |
| 服务停止 | 1001 |

### 断线与服务退出

网络读取或业务分发任务结束时，框架取消该连接其余未完成的任务，然后按
模块顺序调用一次 `when_disconnect(connection)`，关闭连接并移除连接登记。
每个断线回调使用 5 秒超时，失败会记录日志并继续清理其他模块。

服务停止时拒绝新的 WebSocket 连接，关闭已登记连接并等待其清理完成，随后
按模块顺序调用可选的 `shutdown()`。每个 shutdown 使用 10 秒超时，单个模块
失败不阻止其他模块清理。协程超时依赖模块响应取消请求。

### 验证

运行 `python -m unittest discover -s tests -v`。测试只使用临时配置、测试模块
及本机临时监听端口，不加载真实第三方模块、不修改用户资源或真实配置。
前端脚本语法和地址生成接口通过 `node tests/test_framework_urls.cjs` 验证。
`node tests/test_server_controls.cjs` 使用模拟 DOM、存储和网络验证地址输入、
历史恢复、探测、主动断开、重连和旧事件隔离。
`tests/test_frontend_live.py` 使用实际前端内联脚本与 Node 原生网络接口连接
临时 aiohttp 服务，验证两个客户端并存、HTTP 探测、地址切换和主动断开。
这些测试不代表浏览器视觉验收；真实设备上的 file:// 存储、浏览器网络策略、
视频播放与拖动还需实机验收。
