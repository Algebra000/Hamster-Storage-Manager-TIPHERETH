# Classify Shower 模块通信协议

本文档详细描述了分类展示模块（classify\_shower）前端与后端之间的 WebSocket 通信协议。

## 消息格式

### 通用消息结构

控制请求和响应使用 JSON 文本消息，包含以下基础字段；视频分段使用同一 WebSocket 的二进制消息，格式见视频流响应一节：

```json
{
    "command": "命令名称",
    "widgetId": "组件唯一标识",
    ...其他数据字段
}
```

### 字段说明

| 字段       | 类型     | 说明                      |
| -------- | ------ | ----------------------- |
| command  | string | 命令类型，用于标识消息的目的          |
| widgetId | string | 发送消息的前端组件唯一标识，后端可据此回传响应 |

## 前端 → 后端命令

### 1. GET\_ANIME\_PAGE - 获取番剧分页数据

**发送方**：CS\_VideoWidget

**用途**：请求番剧列表分页数据，支持排序和筛选

**请求参数**：

| 参数               | 类型      | 必填 | 默认值    | 说明                           |
| ---------------- | ------- | -- | ------ | ---------------------------- |
| page             | number  | 是  | -      | 页码（从1开始）                     |
| pageSize         | number  | 是  | -      | 每页数量                         |
| sortBy           | string  | 否  | "year" | 排序字段：year / addtime / pinyin |
| sortOrder        | string  | 否  | "DESC" | 排序顺序：ASC / DESC              |
| tagFilterEnabled | boolean | 否  | false  | 是否启用标签筛选                     |
| selectedTags     | array   | 否  | \[]    | 选中的标签ID列表                    |

**示例**：

```json
{
    "command": "GET_ANIME_PAGE",
    "widgetId": "anime_123456_abc",
    "page": 1,
    "pageSize": 10,
    "sortBy": "year",
    "sortOrder": "DESC",
    "tagFilterEnabled": false,
    "selectedTags": []
}
```

### 7. START\_VIDEO\_STREAM / SEEK\_VIDEO\_STREAM - 启动或跳转重封装视频流

**发送方**：CS\_VideoPlayerWidget

**用途**：从指定时间开始输出分片 MP4（fMP4），用于其他容器的实时重封装，以及已标记时间戳异常的普通 MP4 的流式修复。后端每次读取视频元数据中的播放策略，决定是否修复时间戳，前端无需传入修复开关。`SEEK_VIDEO_STREAM` 用于跳转到尚未缓冲的位置，会先取消同一 WebSocket、同一 `widgetId` 的旧流，再建立新流。

| 参数        | 类型     | 必填 | 说明         |
| --------- | ------ | -- | ---------- |
| rootPath  | string | 是  | 番剧文件夹路径    |
| videoPath | string | 是  | 视频文件名或相对路径 |
| startTime | number | 是  | 开始时间，单位为秒  |
| requestId | string | 是 | 本次视频流请求标识，每次开始或跳转时更新 |
| debugSeekId | string | 否 | 调试构建中关联前后端跳转耗时日志的标识，不参与播放控制 |

**示例**：

```json
{
    "command": "START_VIDEO_STREAM",
    "widgetId": "cs_video_player_123456_abc",
    "rootPath": "/path/to/anime",
    "videoPath": "episode_01.mp4",
    "startTime": 120,
    "requestId": "cs_video_player_123456_abc:stream:2"
}
```

跳转请求使用相同结构，将 `command` 改为 `SEEK_VIDEO_STREAM`，并更新 `startTime` 和 `requestId`。实际输出起点由关键帧位置决定，通过 `VIDEO_STREAM_READY.startTime` 返回，可能与请求时间不同。

#### BUFFER_VIDEO_STREAM - 扩展当前流的缓冲范围

首次播放和普通重封装跳转的预缓冲目标为12秒；`SEEK_VIDEO_STREAM` 对应的 READY 中 `playbackMode` 为 `timestamp-repair` 时，前端等待实际开始位置之后有1秒连续可播放缓冲，再设置播放位置，并按用户的播放意图恢复播放。后端为该跳转请求新建的 FFmpeg 进程采用1秒分片时长条件，直到本次进程结束或被取消。播放过程中，前方连续缓冲不超过10秒时，请求将缓冲扩展至当前播放时间之后30秒，已知总时长时不超过视频末尾。`waiting` 事件也可触发补充请求。未缓冲位置跳转的180毫秒防抖期间，前端暂停向旧流发送此命令。

```json
{
    "command": "BUFFER_VIDEO_STREAM",
    "widgetId": "cs_video_player_123456_abc",
    "streamId": "stream-example",
    "bufferUntil": 150
}
```

其中流标识（`streamId` 键）必须对应当前流，允许读取到的位置（`bufferUntil` 键）为完整视频时间轴上的秒数。后端仅在新位置比现值大超过0.05秒时扩展范围；分片起点超出范围时等待下一次放行，因此实际缓冲可能略超请求边界。补充缓冲沿用当前进程，不重新创建流，也不单独返回确认响应。如果处理的是时间戳异常的 MP4，后端在缓冲范围放行后逐段修复时间戳，再发送媒体分片。

### 8. CANCEL\_VIDEO\_STREAM - 取消重封装视频流

请求携带 `command` 和 `widgetId`。后端收到后取消同一 WebSocket、同一 `widgetId` 的准备任务和输出任务，回收主 FFmpeg 进程；如果处理的是时间戳异常的 MP4，还会同时回收辅助解码进程。播放器页面销毁和切换剧集时发送该命令，后端不单独返回取消确认。

后端同时执行防御性回收，不能只依赖该命令：

- 同一播放器启动或 Seek 新流前，先取消旧流；
- WebSocket 正常关闭、异常中断或连接处理任务被取消时，回收该连接的全部流；
- 后端服务退出时，回收所有连接的流并关闭数据库；
- 主 FFmpeg 收到终止请求后，等待退出超过2秒则强制结束；辅助解码进程同时停止并排空输出管道，重复清理共享回收任务。

### 9. CS_GET_COMMENT_INFO - 获取视频评论来源信息

评论面板展开或切换剧集后发送。后端读取视频元数据文件夹中的 `cmif.json`、同级 `__COMMENT__/cm-list.json`、评论数据库及评论阅读记录，响应 `CS_COMMENT_INFO`。

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| requestId | string | 是 | 本次评论信息请求编号 |
| metadataPath | string | 是 | 当前视频对应的 `xxx.files/` 元数据文件夹路径 |

```json
{
    "command": "CS_GET_COMMENT_INFO",
    "widgetId": "cs_video_player_123456_abc",
    "requestId": "cs_video_player_123456_abc_comment_info_1",
    "metadataPath": "D:/Media/Anime/01.files"
}
```

### 10. CS_GET_COMMENT_HTML - 获取一页评论 HTML

切换评论来源、页码、排序或筛选条件时发送。后端查询对应 v1.1 评论数据库，并响应 `CS_COMMENT_HTML`；请求页码超出有效范围时会先响应 `CS_COMMENT_SETPAGE`。

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| requestId | string | 是 | 本次页面请求编号 |
| metadataPath | string | 是 | 用于保存 `__COMMENT-RECORD__.json` 的元数据文件夹 |
| databasePath | string | 是 | 当前来源的 `cm<number>.db` 绝对路径 |
| updateDir | string | 否 | 增量数据库和 `.deletelist` 所在目录；为空时忽略两个已删数据选项 |
| resourcePath | string | 是 | `comment-resource` 与基础资源目录所在的资源根目录 |
| basicResourceFolder | string | 否 | 基础资源文件夹名，默认 `bilibili-resource` |
| bvid | string | 否 | 当前来源 BV 号，用于阅读记录 |
| sortBy | string | 否 | `time` 或 `like` |
| keywordEnabled | boolean | 否 | 是否启用关键词筛选 |
| keyword | string | 否 | 关键词 |
| page | number | 否 | 请求页码，从 1 开始 |
| pageSize | number | 否 | 每页顶层评论数，范围 1～200 |
| markDeleted | boolean | 否 | 是否用淡粉色背景标识已删除的评论或回复 |
| onlyDeleted | boolean | 否 | 是否只查询已删除数据；与 `markDeleted` 相互独立 |
| onlyVip | boolean | 否 | 是否只显示大会员评论 |
| wordFilterEnabled | boolean | 否 | 是否启用字数筛选 |
| wordCount | number | 否 | 字数边界 |
| wordDirection | string | 否 | `above` 或 `below` |
| updateReadRecord | boolean | 否 | 是否保存当前来源、页码和单页数量 |
| updatePageSizeDefault | boolean | 否 | 是否把单页数量写入全局默认配置 |

```json
{
    "command": "CS_GET_COMMENT_HTML",
    "widgetId": "cs_video_player_123456_abc",
    "requestId": "cs_video_player_123456_abc_comment_html_2",
    "metadataPath": "D:/Media/Anime/01.files",
    "databasePath": "D:/Media/Anime/__COMMENT__/cm1.db",
    "updateDir": "D:/Media/Anime/__COMMENT__/update",
    "resourcePath": "D:/Media/Anime/__COMMENT__",
    "basicResourceFolder": "bilibili-resource",
    "bvid": "BV1XXXXXXXXX",
    "sortBy": "time",
    "keywordEnabled": false,
    "keyword": "",
    "page": 1,
    "pageSize": 20,
    "markDeleted": true,
    "onlyDeleted": false,
    "onlyVip": false,
    "wordFilterEnabled": false,
    "wordCount": 100,
    "wordDirection": "above",
    "updateReadRecord": true,
    "updatePageSizeDefault": false
}
```

### 11. CS_SET_COMMENT_SOURCEINFO - 修改评论来源信息

当前用于修改 `__COMMENT__/cm-list.json` 中指定来源的 `src-name`。后端通过 BV 号定位来源；为避免任意字段和任意文件写入，当前只接受文件名为 `cm-list.json`、位于已配置资源根目录内的文件，并只允许修改 `src-name`。

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| requestId | string | 是 | 修改请求编号 |
| cmListPath | string | 是 | 对应共享评论目录中 `cm-list.json` 的绝对路径 |
| bvid | string | 是 | 要修改的评论来源 BV 号，即 `cm-list.json` 的键 |
| key | string | 是 | 要修改的键；当前仅允许 `src-name` |
| value | string | 是 | 新来源名称，去除首尾空白后长度为 1～200 |

```json
{
    "command": "CS_SET_COMMENT_SOURCEINFO",
    "widgetId": "cs_video_player_123456_abc",
    "requestId": "cs_video_player_123456_abc_comment_source_info_3",
    "cmListPath": "D:/Media/Anime/__COMMENT__/cm-list.json",
    "bvid": "BV1XXXXXXXXX",
    "key": "src-name",
    "value": "新的来源名称"
}
```

```json
}
```

播放策略来自视频同级的 `<完整视频文件名（含扩展名）>@meta/__meta`，例如 `episode_01.mp4@meta/__meta`。只有普通 `.mp4` 的该 JSON 对象中 `mp4-timestamps-valid` 明确为布尔值 `false` 时，才返回示例中的修复策略。缺少文件或键、读取及解析失败、文件超过64 KiB、路径越界，或者值为其他类型时，均使用默认策略；字符串 `"false"` 和数字0不会触发。该标记表示时序异常，不等同于缺少 `ctts` 表，播放流程不自动生成或改写标记。

前端同时核对 `widgetId`、`requestId` 和 `videoPath`，只接受当前请求的响应。策略触发时显示黄色提示“该 MP4 的显示时间戳异常，将修复时间轴并采用缓冲播放。”，随后通过视频流接口接收修复后的 fMP4；未触发时沿用原有扩展名播放规则。

前端收到 `video-stream` 为 `H265` 时使用视频元素的 `canPlayType` 检测 HEVC 支持。支持时播放原视频；不支持且 `compat_file` 非空时直接播放兼容文件，观看记录和弹幕仍关联原剧集。不支持且兼容路径为空时播放器保持黑屏，并发送红底提示“本设备不支持H265且无可用的兼容视频来源，因此无法播放该视频”。

### 7. VIDEO\_STREAM\_READY / VIDEO\_STREAM\_UNSUPPORTED / VIDEO\_STREAM\_ENDED / VIDEO\_STREAM\_ERROR

`VIDEO_STREAM_READY` 表示当前请求已完成播放信息准备，前端据此建立 `SourceBuffer` 并等待媒体分片。处理时间戳异常 MP4 时的响应参考示例：

```json
{
    "command": "VIDEO_STREAM_READY",
    "widgetId": "cs_video_player_123456_abc",
    "videoPath": "episode_01.mp4",
    "requestId": "cs_video_player_123456_abc:stream:2",
    "streamId": "stream-example",
    "playbackMode": "timestamp-repair",
    "timestampResult": "streaming",
    "startTime": 118.5,
    "requestedStartTime": 120,
    "bufferHighWaterSeconds": 30,
    "duration": 1422.05,
    "videoCodec": "h264",
    "videoSupported": true,
    "sourceAudioCodec": "aac",
    "audioCodec": "aac",
    "audioTranscoded": false,
    "mimeType": "video/mp4; codecs=\"avc1.640028,mp4a.40.2\""
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| videoPath | string | 本次请求的视频路径 |
| requestId | string | 本次开始或跳转请求的标识，后端原样返回 |
| streamId | string | 后端为本次流生成的标识，每次开始或跳转重新生成 |
| playbackMode | string | 普通重封装为 `remux`，时间戳修复为 `timestamp-repair` |
| timestampResult | string | 普通重封装为 `not-requested`，逐段修复为 `streaming` |
| startTime | number | 实际开始时间，单位为秒，用于设置播放位置和 `SourceBuffer.timestampOffset` |
| requestedStartTime | number | 用户请求的开始时间，单位为秒 |
| bufferHighWaterSeconds | number | 缓冲高水位，当前为30秒 |
| duration | number | 原视频总时长，单位为秒；未解析到时为0 |
| videoCodec | string | 视频编码名称 |
| videoSupported | boolean | 视频编码是否通过后端支持检查，READY 中为 `true` |
| sourceAudioCodec | string / null | 原音频编码，无音轨时为 `null` |
| audioCodec | string / null | 输出音频编码，无音轨时为 `null` |
| audioTranscoded | boolean | 是否将音频实时转为48 kHz、128 kb/s的 AAC-LC |
| mimeType | string | 前端检查编码兼容性、创建 `SourceBuffer` 使用的 MIME 字符串 |

示例表示请求第120秒，从第118.5秒的实际关键帧位置开始输出。前端核对 `widgetId`、`requestId` 和 `videoPath` 后才接受 READY。`timestampResult=streaming` 表示后续分片在发送前逐段修复，不表示已完成全片校验；修复使用分片 `trun` 中的显示时间偏移，不创建中间视频，也不改写原 MP4。

其他响应均带有 `widgetId` 和 `streamId`，具体含义如下：

- `VIDEO_STREAM_UNSUPPORTED`：视频编码不在支持列表时返回，另含 `videoPath`、`requestId`、`mediaType`（当前为 `video`）、`videoCodec`、`supportedVideoCodecs` 和 `message`。此时不启动正式输出流，也不发送媒体二进制数据。
- `VIDEO_STREAM_ENDED`：FFmpeg 已正常输出到文件末尾。前端等已接收分片追加完成后结束媒体源，不表示播放头已经到达末尾。
- `VIDEO_STREAM_ERROR`：包含可向用户显示的 `error` 字段。准备阶段的错误还带有 `videoPath` 和 `requestId`，前端据此排除过期请求；输出阶段的错误按当前 `streamId` 匹配。修复时无法可靠恢复时序、样本不匹配或解码失败也通过此响应返回，前端停止该流并显示错误原因。

媒体内容不封装在 JSON 中，而是使用同一个 WebSocket 的二进制消息传输。每条二进制消息格式如下：

```text
4 bytes  magic: HSV1
4 bytes  大端无符号整数：JSON 头长度 N
N bytes  UTF-8 JSON 头（type、streamId、widgetId、sequence、segmentType）
其余      fMP4 二进制数据
```

JSON 头参考示例：

```json
{
    "type": "VIDEO_STREAM_CHUNK",
    "streamId": "stream-example",
    "widgetId": "cs_video_player_123456_abc",
    "sequence": 0,
    "segmentType": "init"
}
```

其中 `type` 固定为 `VIDEO_STREAM_CHUNK`；`widgetId` 和 `streamId` 用于匹配当前播放器与视频流，取消后迟到的旧流数据会被丢弃。`sequence` 在每个流内从0递增；`segmentType` 为 `init` 时表示包含轨道配置的初始化段，为 `media` 时表示由 `moof` 和 `mdat` 组成的媒体段。前端先追加初始化段，再依次追加媒体段。普通重封装和时间戳修复使用相同的传输格式。

## 消息处理机制

### 前端消息发送

所有组件通过 `sendCommand(command, data)` 方法发送消息：

```javascript
sendCommand(command, data = {}) {
    if (socket && socket.isConnected()) {
        socket.send(JSON.stringify({
            command: command,
            widgetId: this.widgetId,
            ...data
        }));
    }
}
```

### 前端消息接收

前端通过 `message_proc_func_list` 数组注册消息处理函数：

```javascript
this.messageHandler = (data) => {
    if (data.command === 'CS_VIDEO_DATA' && data.widgetId === this.widgetId) {
        // 处理弹幕数据
    }
};
message_proc_func_list.push(this.messageHandler);
```

### WidgetId 命名规则

| 组件                    | WidgetId 格式                   | 示例                             |
| --------------------- | ----------------------------- | ------------------------------ |
| CS\_VideoWidget       | anime\_时间戳\_随机字符串             | anime\_123456\_abc             |
| CS\_AnimeDetailWidget | anime\_detail\_番剧ID           | anime\_detail\_1               |
| CS\_VideoPlayerWidget | cs\_video\_player\_时间戳\_随机字符串 | cs\_video\_player\_123456\_abc |
