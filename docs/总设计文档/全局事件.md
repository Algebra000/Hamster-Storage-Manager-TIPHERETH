# 全局事件

## 接口与分发规则

MainUI.html 在加载布局与功能模块前定义：

```javascript
const event_handler_list = [];
function frame_dispatch_event(event, wParam = null, lParam = null) { /* 框架实现 */ }
```

处理函数签名为 `handler(event, wParam, lParam)`，没有 target 参数。
`event` 必须为字符串；`wParam`、`lParam` 类型不限，由每个事件自行定义。
定向事件可以把目标对象放入任一参数，处理函数自行筛选。
自定义事件建议使用模块前缀，避免与框架或其他模块重名。

分发按调用时的列表快照和注册顺序同步执行。新增、移除处理函数只影响下一次分发。
返回值不截断广播，异常记录后继续执行其他处理函数；返回 Promise 时不等待，
但框架记录其 rejection。参数不会复制，处理函数不得修改共享参数。
框架的 WebSocket 事件详情对象使用 Object.freeze 做浅冻结。

动态组件应在创建时注册、在页面 cleanFuncList 中移除同一个函数引用。
异步任务应自行核对连接 ID、传输编号和组件存活状态，丢弃过期结果。
这些是前端进程内事件，不会自动通过网络发送给后端。

```javascript
function cs_handler(event, wParam, lParam) {
    if (event === 'CS_REFRESH' && wParam === widget) widget.loadPage(lParam.page);
}
event_handler_list.push(cs_handler);
frame_dispatch_event('CS_REFRESH', widget, {page: 1});
page.cleanFuncList.push(() => {
    const index = event_handler_list.indexOf(cs_handler);
    if (index !== -1) event_handler_list.splice(index, 1);
});
```

## 预定义的事件

### 1. WS_CONNECTED: websocket 连接成功

当前 WebSocket 通过后端版本验证并成为可用传输时触发，每条成功传输一次。
仅收到浏览器 onopen 尚不触发；首次连接和重连成功均触发。

- `wParam`：string，逻辑会话 ID，对应 socket.connectionId。
- `lParam`：只读详情对象，字段如下。

| 字段 | 类型 | 定义 |
| --- | --- | --- |
| transportId | number | 当前连接管理器内递增的传输编号；失败尝试也占编号，因此可以跳号 |
| url | string | WebSocket 服务地址，不附加 connectionId 查询参数 |
| reconnected | boolean | 此管理器此前是否有成功连接；首次尝试失败后第一次成功仍为 false |
| resumed | boolean | 后端握手的 resumed 是否为 true；后端重启或会话到期后可以为 false |

首次成功时，先设置 socket.isConnected() 为 true，执行 when_connect_func_list，
再广播本事件；重连成功不重复执行 when_connect_func_list。
事件处理函数此时可以发送命令。本事件不保证后端已完成任意模块业务初始化。

```javascript
frame_dispatch_event('WS_CONNECTED', connectionId, {
    transportId: 3, url: 'ws://host:8768/ws', reconnected: true, resumed: true
});
```

### 2. WS_DISCONNECTED: websocket 连接失效

此前通过版本验证的当前传输失效时触发。心跳超时无需等待浏览器 onclose。
先将 socket.isConnected() 设为 false，再广播事件；每条成功传输最多触发一次。
尚未连接成功的候选失败不触发；已被接替传输的迟到事件不触发。

- `wParam`：string，逻辑会话 ID。
- `lParam`：只读详情对象，字段如下。

| 字段 | 类型 | 定义 |
| --- | --- | --- |
| transportId | number | 本次失效的传输编号，与此前 WS_CONNECTED 对应 |
| url | string | WebSocket 服务地址 |
| reason | string | 下表定义的原因 |
| code | number 或 null | 实际收到的关闭码；尚无关闭事件时为 null，不伪造 1006 |
| detail | string | 附加说明或对端关闭原因；可能为空字符串 |
| willReconnect | boolean | 事件产生时框架是否计划重连；不代表重连一定成功 |

| reason | 含义 | willReconnect |
| --- | --- | --- |
| heartbeat-timeout | 连续 3 秒没有有效心跳应答 | true |
| transport-close | 当前底层连接关闭 | true |
| send-failure | 框架心跳探测发送抛出异常 | true |
| manual-disconnect | 主动断开／调用 socket.close() | false |
| server-switch | 显式连接服务器前结束旧连接管理器 | false |
| manual-reconnect | 调用 socket.reconnect() 重建传输 | true |

普通业务 send() 的失败仍以返回 false 表达，不自动产生 send-failure 事件。

意外失联先广播本事件，再启动重连，不调用 when_disconnect_func_list。
主动断开先停止重连并尽力发送 SESSION_DISCONNECT，再广播本事件，最后执行
when_disconnect_func_list 清理页面。如果此前已广播失联，主动结束逻辑会话
只执行清理回调，不重复广播本事件。

## 生命周期边界

when_connect_func_list / when_disconnect_func_list 管理逻辑会话初始化与清理；
WS_CONNECTED / WS_DISCONNECTED 描述底层传输变化，不能混为一谈。
本次仅提供事件基础设施，FFmpeg 流恢复尚未订阅这些事件。
