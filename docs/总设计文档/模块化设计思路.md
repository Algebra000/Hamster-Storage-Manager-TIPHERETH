# 关于模块化设计

以HTML为基础的前端应用主要由各个功能模块以及组织摆放这些功能模块的布局模块两大部分构成，仓鼠存储管理器的设计目的之一为实现这两大部分的高度可定制化和模块化。

***

## 布局模块：

主界面 `MainUI.html` 在加载所有的功能模块之前会首先加载 `frontend/` 目录下的布局模块 `frame.js`（必要模块），`frame.js` 的作用是将界面分成几部分区域(也可以实现分页、下拉框等等分配有限屏幕空间的方法，不同的布局模块采用不同的设计)，其至少应实现以下方法：

1. `get_block(index)`：传入区域索引，返回该区域的块级元素(div)供功能模块使用，就像将这个div作为窗口分配给了这个功能模块，功能模块可以在这个div上实现自己的界面和各种功能。

   关于区域索引：区域索引具体代指的区域由 `frame.js` 定义，可以最多有有限块区域(index超出范围或已经被某个功能模块使用就返回null)，也可以不限数量（例如可以设计成类似windows窗口这样的效果，一个窗口一块区域，可以任意拖动，相互之间可以重叠）

   注意一个规范：这个函数应该在 `set_when_show(index, func)` 传入的回调函数中以及在这之后的时机调用，过早调用可能会导致与这个索引对应的块级元素此时还没初始化。例如某个模块使用 `create_new_block` 建立临时区域，然后调用 `show_module` 来调用活跃回调函数，如果 `get_block()` 在模块加载完毕就被调用那么该函数将会失败，因为临时区域还没有被建立。

   还有在功能模块里，尽量每次使用区域时都调用 `get_block()` 函数，这是因为分配给该功能模块的区域可能会变，这意味之前获得的区域已经废弃。

2. `set_when_show(index, func)` 传入某功能模块的区域索引与活跃回调函数，当该模块的区域显示到屏幕上时将调用该回调函数，该回调函数通常用于将该模块启动或转为活跃状态。
3. `set_when_hide(index, func)` 传入某功能模块的区域索引与睡眠回调函数，当该模块的区域从屏幕上消失时将调用该回调函数，该回调函数通常用于将该模块关闭或转为睡眠状态。
4. `create_new_block(block)` 向frame.js注册一个临时区域，传入这个区域的element对象，返回注册成功的区域索引。使用这个区域索引在别的地方调用 get\_block() 即可获得这个 element 对象。
5. `show_module(index)` 执行索引为index这个区域相关联模块的活跃回调函数，常用于唤醒某模块
6. `hide_module(index)` 执行索引为index这个区域相关联模块的睡眠回调函数，常用于关闭、待机某模块
7. `new_page()` 新建空白页，当前页面将被隐藏(display属性)，新建的空白页将压入页面管理栈，即是将在页面上显示，返回新建的这个页面。

   返回的这个dom元素对象有自定义成员 `cleanFuncList`，这样管理该页面的模块可以向其中push一个清理函数，执行`pop_page`时将执行 `cleanFuncList` 里所有的函数再弹出页面。

8. `pop_page(num)`：从页面管理栈里弹出 num 个对象，页面将显示弹出后栈指针指向的页面。返回实际弹出的页面数量。

9. `frame_show_notice(text, durationMs = 5000, backgroundColor = '#FFFEFE', showCloseButton = true, textColor = null)`：显示一条内容为 `text` 的通知，显示时长（`durationMs` 参数）单位为毫秒，设为0时持续显示；背景色（`backgroundColor` 参数）接受有效 CSS 颜色，例如 `#FFFEFE`；`showCloseButton` 参数接受布尔值，是否显示关闭按钮；`textColor` 参数决定通知文字颜色，也接受有效 CSS 颜色。
	返回带 `close()` 方法的句柄，调用 `close()` 可主动关闭该通知。功能模块在页面 DOM 就绪后调用。



### 关于页面管理栈：

页面管理栈是前端用来管理页面树的结构，它决定当前显示哪个页面。只有栈指针指向的页面会被显示，其他页面均隐藏(display属性)。页面管理栈里默认且最少有一个页面，即是这个布局模块的根页面，就是前端打开未加载任何功能模块时显示的那个页面，其无法被弹出。

## 功能模块：

### 功能模块的前端部分

功能模块的前端部分应当设计为方便装卸的形式，在`<head>`里加上`<script>`标签引用它的js文件(例如example.js)，无需其他操作就可以实现其功能。

前端部分的第一行应该是定义该功能模块使用的区域索引的变量定义，例如 example.js的第一行： `const EXAMPLE_JS_MODULE_INDEX = 2` 表示example.js将使用frame.js给出的索引为2的区域来绘制它自己的界面。这个变量可以根据用户的需要更改。

另外，`MainUI.html` 在加载所有模块(包括布局模块)的代码前会建立`when_connect_func_list`、`when_disconnect_func_list`、`message_proc_func_list`、`binary_message_proc_func_list`、`onload_func_list`这几个函数列表。其中：


1. `message_proc_func_list` 里的函数形如 `function(data)`，`data` 为一JSON实例，是收到的JSON消息。

2. `binary_message_proc_func_list` 里的函数形如 `func(header, payload)`。`header`为一JSON实例，是收到的二进制流的信息头。`payload` 是一 `ArrayBuffer` 实例，是收到的二进制流。

`MainUI.html` 在 `BasicEvent.when_connect()`、`BasicEvent.when_disconnect()`、`messageProc`、`window.onload` 函数中会遍历对应的函数列表并调用这些函数，因此功能模块如果要在这些时候做些什么就往这些列表里加入自己的函数。

前端部分至少应实现以下逻辑：

1. 初始化：向 `MainUI.html` 中加入所需的`<style>`标签和各种html标签结构，并在获得的区域绘制初始界面
2. 其各种变量、方法、函数的命名既要见名知意又要足够独特以确保不会与其他模块里的变量意外重名。一般使用加上模块名称前缀的方法。

### 功能模块的后端部分:

`back.py` 运行时会读取 `./config/` 目录下的 `module_config.json`，这个配置文件会告诉`back.py` 从什么地方加载哪些模块，然后 `back.py` 加载这些模块。

每一个后端模块实际上是一个类，这个类至少实现以下方法：

- 构造方法：`__init__(self, global_config)`，其中 `global_config` 是全局配置字典，即 `global_config.json` 的内容。
- `(async) when_connect(websocket)`:将在逻辑会话首次建立时调用。
- `(async) when_disconnect(websocket)`:将在逻辑会话终止时调用（不包括临时网络中断）。
- `(async) message_proc(websocket, data)`:消息处理函数，接收到消息时调用。

其中传入 `when_connect`、`when_disconnect`、`message_proc` 回调函数的 `websocket`
实际是框架创建的 `FrameworkConnection` 对象，模块无需自行创建。其简化签名如下：

```python
class FrameworkConnection:
    # 发送文本或二进制消息；JSON 对象需由模块先序列化，调用时需要 await。
    async def send(self, data): ...

    # 关闭当前连接，可指定关闭码及原因，调用时需要 await。
    async def close(self, code=1000, reason=''): ...

    # 将允许目录内的文件路径转换为含协议、主机和端口的绝对 HTTP(S) URL；同步方法，无需 await。
    def resource_url(self, file_path): ...

    # 将内存 bytes 登记为独立的绝对 HTTP(S) URL，每次调用均创建新资源。
    def blob_url(self, data_name, data: bytes): ...

    # 传入创建时返回的完整 URL，删除本连接的资源并返回是否存在；同步方法，无需 await。
    def delete_blob_url(self, blob_url: str): ...

    # 读取下一条上行消息；仅供框架内部使用，模块不得调用，以免抢走消息。
    async def recv(self): ...

    # 只读属性，表示连接是否已关闭，使用 websocket.closed 读取。
    @property
    def closed(self): ...
```

同时这个模块应该包含以下全局函数：

1. `create_module(global_config, back_version)` 形参分别对应全局配置字典和后端版本字符串(这避免一些模块在不适合的后端版本上加载，若版本不匹配返回空值或0)，返回这个后端模块包含的类对象。

2. `settings()` 用于在安装时通过命令行设置模块参数的函数。该函数将在安装时调用，作为安装向导 `install.py` 的一个环节。

后端使用 websocket 发送二进制块应当遵循的二进制结构：

```text
| 4字节魔数 0x48535631 | JSON字符串长度(int32,大端序)|    ......(二进制流的信息头JSON字符串(UTF8))......    |   二进制流 ......
```

#### 资源文件 URL 生成标准

TIPHERETH 版本为了实现远程访问，对 `global_config` 中 `base_dir` 字段里所有根目录都以http 协议在 `/resources/` 路由下开放。这就涉及一套路径和URL的标准转换规则。假设后端在 IP `xxx.xxx.xxx.xxx:8768` 上开放，URL 路径格式为：

```text
http://xxx.xxx.xxx.xxx:8768/resources/xxxxx/......
```

假定某资源文件在 `base_dir` 字段列表里索引为 n 的根目录下，相对地址为 `./XXXXXXXXX`，则该资源的 `rootId` 是 `n`。若根目录不存在、不可访问或受保护，则不登记但保留其 `rootId` 编号空位，后面根目录的索引不前移。则该文件可以通过该 URL 访问:

```text
http://xxx.xxx.xxx.xxx:8768/resources/n/XXXXXXXXX
```

例如后端在 `http://192.168.1.20:8768` 开放，配置为：

```json
{
    "base_dir": ["D:/视频", "E:/图片"]
}
```

假设客户端通过 `ws://192.168.1.20:8768/ws` 连接，文件 `E:/图片/cover #1.jpg` 对应的绝对 URL 为：

```text
http://192.168.1.20:8768/resources/1/cover%20%231.jpg
```

无效或未登记的 rootId、文件缺失或目录请求返回 404；非法路径或访问被禁止时返回 403。
具体映射与文件检查尽可能由框架完成，模块不要绕过这些检查自行发布文件。


后端功能模块通过传入 `when_connect`、`when_disconnect`、`message_proc`回调函数的 `websocket` 连接对象调用 `websocket.resource_url(file_path)`，得到绝对 HTTP(S) URL。

#### 二进制数据 URL 

通过传入 `when_connect`、`when_disconnect`、`message_proc`回调函数的 `websocket` 连接对象调用 `websocket.blob_url(data_name, data: bytes)` 可以生成封面、缩略图等内存数据的临时访问地址，其形参：

1. `data_name` 为非空字符串，仅作为数据名称，建议带文件扩展名
供后端推断 Content-Type；无法识别时使用 `application/octet-stream`。

2. `data` 是二进制数据串，`bytes` 类型。

这两个方法都在框架事件循环中同步调用，不需要 await。

每次调用都创建新的 URL，即使名称和内容相同也不覆盖旧资源；不同连接互不影响。
删除必须传入创建时返回的原始完整 URL；不存在、已删除、经过修改或其他连接的 URL
返回 False，非字符串参数抛出 TypeError。

生成的 URL 格式为 `http(s)://主机:端口/blobs/{随机标识}/{data_name}`，地址来源与 `resource_url()` 相同，
前端直接访问，不应解析其标识。这是后端 HTTP 地址，不是浏览器的 `blob:` 地址。
URL 以经过百分号编码的 data_name 结尾，UUID 位于中间。名称不能为 `.`、`..`，
不能含路径分隔符或控制字符；中文、空格、`#` 等字符会自动编码。
读取时同时校验 UUID 和名称，更改名称会返回 404。

```python
# 在后端模块回调中登记数据并发送 URL。
url = websocket.blob_url('example_cover.png', image_bytes)
await websocket.send(json.dumps({'command': 'EXAMPLE_COVER', 'url': url}))

# 不再需要该数据时主动释放；不存在时返回 False。
deleted = websocket.delete_blob_url(url)
```

HTTP 接口支持 GET、HEAD 和跨源 OPTIONS，使用 `Cache-Control: no-store`。
内存响应不支持 Range，转存文件后由 FileResponse 支持 Range，模块不要依赖 blob 一定可分段读取。

`global_config.json` 中的 `http-url-config` 控制所有连接共享的 blob 内存容量：

启动时若缺少整个 `http-url-config` 字段，框架会将下面的默认配置原子补写到文件中，
保留其他配置；已有该字段时不会覆盖其自定义值。

```json
"http-url-config": {
    "max-blob-bytes": 104857600,
    "tmp-blob-file": false
}
```

- `max-blob-bytes`：内存中已登记 blob 的总字节数上限，非负整数，默认 100 MiB。
- `tmp-blob-file`：超限时是否允许转存临时文件，默认 false。
  为 false 时在超限情况下调用 `blob_url()` 将失败，不产生 URL；为 true 时按创建顺序，将最早仍在内存中的 blob 逐个转存到 `backend/classify_shower/temp`，直到容得下新数据。
  转存这一步骤本身是独立的，不改变其对应的旧 URL 的有效性，不影响其他连接对旧 URL 的访问。
- 单个新 blob 本身超过限额时，启用转存则直接落盘，否则失败；
  写盘失败抛出 OSError，同时保留已有数据（部分可能已成功转存）。

配置在启动时读取，修改后需重启生效。
随机 URL 不绑定下载者身份，持有地址的其他客户端也可读取。

## 回调函数的调用顺序

```text
初始化几个函数列表
		↓
执行 frame.js
		↓
加载各个功能模块
		↓
定义各个基础方法类(BasicEvent)
		↓
定义WebSock相关函数、注册window.onload
		↓
页面加载完成
		↓
按顺序执行onload_func_list里的函数
如果frame.js往onload_func_list里注册过就最先执行frame.js注册的函数
		↓
尝试连接后端
		↓
成功连接后端
		↓
console.log('连接成功');
		↓
遍历执行when_connect_func_list里的函数
		↓
              ......
```

### 收到后端文本消息时

```text
WebSocket.onmessage 调用异步 messageProc(event)
		↓
确认消息不是 ArrayBuffer/Blob 后执行 JSON.parse(event.data)
		↓
如果 command 是 SET_NOWPATH，MainUI.html 先更新根目录输入框
		↓
按当前数组顺序遍历 message_proc_func_list，并把同一个 data 对象传给每个回调
```

当前静态注册的 treemap 消息处理函数通常排在前面；番剧列表、详情页、播放器等组件的 handler 在组件 render() 时动态 push，调用顺序取决于组件创建顺序。各 handler 必须自行检查 command 和 widgetId，只处理属于自己的消息。页面 cleanFuncList 会移除已销毁组件的动态 handler。

### 收到后端二进制消息时

```text
messageProc(event) 检测到 ArrayBuffer 或 Blob
		↓
Blob 先转换为 ArrayBuffer
		↓
检查至少8字节、HSV1魔数(0x48535631)和JSON头长度是否合法
		↓
解析 UTF-8 JSON header，并从剩余字节切出 payload
		↓
按注册顺序遍历 binary_message_proc_func_list，调用 func(header, payload)
```

播放器组件在 render() 时动态注册 binaryMessageHandler，在页面清理时移除。每个处理函数应检查 type、widgetId、streamId 等字段，避免把其他组件或已经取消的旧流数据写入当前播放器。

### WebSocket 传输与逻辑会话

前端每次主动连接创建随机 UUID `socket.connectionId`，在 `/ws?connectionId=...`
中传给后端。自动重连及 `socket.reconnect()` 保持此 ID；旧传输的事件代号仍递增，
用于丢弃迟到事件。ID 应作为会话凭据保护，不作为公开业务标识。

意外断线只将 `socket.isConnected()` 设为 false，并每隔 1 秒持续尝试重连。
每次实际发起重连（包括心跳超时重建、连续失败后的重试）均显示浅红色（#F8D7DA）、
15 秒的 `frame_show_notice` 通知。首次正常连接不显示重连通知。
重连通过版本验证后显示浅绿底（#D1E7DD）的“重新连接成功。”通知，持续 15 秒；
仅底层连接建立、尚未通过版本验证时不提示成功。
不调用 `BasicEvent.when_disconnect()` 或 `when_disconnect_func_list`，不弹出页面，
不销毁播放器。重连通过版本验证后恢复发送，但不重复调用前端连接回调。
前端 `send()` 在传输不可用时返回 false，不缓存或重放业务命令。

用户点击“断开”（以及显式切换服务器、调用 socket.close）才执行原断线清理，
并发送框架消息 `{"command":"SESSION_DISCONNECT"}`。该消息由框架消费，不分发模块。
若传输已断，前端尝试临时连接同一 ID 发送结束消息；完全离线时无法保证送达，
由后端超时回收。关闭网页不主动发送结束消息，服务端等待离线超时。

后端按 ID 保存同一个 FrameworkConnection 对象，重连只替换其底层 WebSocket。
每次传输均先发送 BACKEND_VERSION（含 connectionId、resumed），再发送 SET_NOWPATH。
后端模块 when_connect 只在新会话创建时调用；意外断线不调用 when_disconnect。
业务消费者与有界输入队列在会话内保留；离线期间发送协程等待恢复，不另建无界缓存。
发送重试不提供业务“恰好一次”保证，模块仍应使用请求 ID 排除重复或过期消息。
同一 ID 允许新传输接替旧传输。握手串行完成，版本和路径消息先发送，再将同一个
FrameworkConnection 绑定到新 WebSocket，异步关闭旧传输。旧传输的消息停止分发，
迟到的关闭与 finally 不得清理新传输、启动过期计时或调用模块断线回调。
接替不重新初始化模块，不改变连接 ID，也不自动重放未确认的业务命令。

前端每 1 秒发送 `{"command":"HEARTBEAT_PING","sequence":整数}`，后端网络读取层
立即返回 `{"command":"HEARTBEAT_PONG","sequence":原序号}`，不经过模块业务队列。
前端使用单调时钟；从握手完成或最后一次有效应答起满 3 秒无有效应答，就立即尝试
新建 WebSocket，不等待旧连接 onclose。只接受当前传输已发探测的序号，心跳不分发模块。
重建期间 send 返回 false；旧传输保持到新传输版本验证成功再关闭，旧事件已隔离。
每个管理器同时最多保留一条旧传输和一个新建候选，不并行发起多次重连。
连接建立仍有 10 秒超时，版本等待 5 秒超时后继续重试；明确版本不兼容仍停止连接。
浏览器后台节流或事件循环阻塞可能推迟计时器，3 秒是检测阈值而非实时保证。

`backend/config/global_config.json` 中 `connect_timeout` 为正整数秒数，默认 1200。
缺失时启动原子补写，其他配置保留；无效值报错。计时从传输断开后开始，
成功重连取消计时；下一次断线重新计时。在线连接不会因为超过 20 分钟被结束。
超时、主动中断或服务退出时，会话终止：取消业务任务、调用模块 when_disconnect，
释放 blob 资源并移除 ID。到期后同一 ID 再次接入会创建新会话（resumed=false），
旧模块状态无法恢复。前端页面保留不等于服务器已过期的业务状态可以恢复。

blob URL 在短暂断线期间保留，会话终止才释放。普通文件 URL 不随会话销毁。
`closed` 仍表示当前底层 WebSocket 状态，不等价于逻辑会话已经终止。
未带 connectionId 的旧客户端继续使用原先每条 WebSocket 独立清理的方式。

### 布局区域和页面管理回调

show\_module(index)：仅当 block\_show\_list\[index] 为 false 时调用对应 when\_show\_callback\_list\[index]；成功后标记为已显示。

hide\_module(index)：仅当 block\_show\_list\[index] 为 true 时调用对应 when\_hide\_callback\_list\[index]；成功后标记为已隐藏。

new\_page()：先隐藏当前页面并创建新页面，然后依次调用所有固定区域已有的 when\_hide 回调，把固定区域标记为隐藏。

pop\_page(num)：按出栈顺序处理页面。每个页面先按 cleanFuncList 数组顺序执行清理函数，再移除DOM；回到根页面后依次执行所有固定区域的 when\_show 回调并标记为显示。

### 后端模块回调顺序

backend/back.py 启动时按 backend/config/module\_config.json 中 modules 的书写顺序加载启用的模块，模块实例保存在 module\_manager.modules 中。当前顺序是 treemap，然后 classify\_shower。

建立连接后：先向前端发送 SET\_NOWPATH，再按模块顺序 await module.when\_connect(websocket)。

收到前端JSON消息后：按模块顺序 await module.message\_proc(websocket, data)。前一个模块处理完成后才调用下一个模块。

逻辑会话主动结束、离线超时或服务退出时：按模块顺序 await module.when_disconnect(websocket)。临时传输断开不清理会话。单个模块清理失败会被记录，但不会阻止其他模块继续清理。

后端服务退出时：main() 的 finally 按模块顺序查找并调用可选的 module.shutdown()，用于回收仍存活的FFmpeg流、数据库连接等服务级资源。
