# 关于模块化设计

以HTML为基础的前端应用主要由各个功能模块以及组织摆放这些功能模块的布局模块两大部分构成，仓鼠存储管理器的设计目的之一为实现这两大部分的高度可定制化和模块化。

***

## 布局模块：

主界面 `MainUI.html` 在加载所有的功能模块之前会首先加载同一目录下的布局模块 `frame.js`（必要模块），`frame.js` 的作用是将界面分成几部分区域(也可以实现分页、下拉框等等分配有限屏幕空间的方法，不同的布局模块采用不同的设计)，其至少应实现以下方法：

1. `get_block(index)`：传入区域索引，返回该区域的块级元素(div)供功能模块使用，就像将这个div作为窗口分配给了这个功能模块，功能模块可以在这个div上实现自己的界面和各种功能。

   关于区域索引：区域索引具体代指的区域由 `frame.js` 定义，可以最多有有限块区域(index超出范围或已经被某个功能模块使用就返回null)，也可以不限数量（例如可以设计成类似windows窗口这样的效果，一个窗口一块区域，可以任意拖动，相互之间可以重叠）

   注意一个规范：这个函数应该在 `set_when_show(index, func)` 传入的回调函数中调用，过早调用可能会导致与这个索引对应的块级元素此时还没初始化。例如某个模块使用 `create_new_block` 建立临时区域，然后调用 `show_module` 来调用活跃回调函数，如果 `get_block()` 在模块加载完毕就被调用那么该函数将会失败，因为临时区域还没有被建立。

   还有在功能模块里，尽量每次使用区域时都调用 `get_block()` 函数，这是因为分配给该功能模块的区域可能会变，这意味之前获得的区域已经废弃。

2. `set_when_show(index, func)` 传入某功能模块的区域索引与活跃回调函数，当该模块的区域显示到屏幕上时将调用该回调函数，该回调函数通常用于将该模块启动或转为活跃状态。
3. `set_when_hide(index, func)` 传入某功能模块的区域索引与睡眠回调函数，当该模块的区域从屏幕上消失时将调用该回调函数，该回调函数通常用于将该模块关闭或转为睡眠状态。
4. `create_new_block(block)` 向frame.js注册一个临时区域，传入这个区域的element对象，返回注册成功的区域索引。使用这个区域索引在别的地方调用 get\_block() 即可获得这个 element 对象。
5. `show_module(index)` 执行索引为index这个区域相关联模块的活跃回调函数，常用于唤醒某模块
6. `hide_module(index)` 执行索引为index这个区域相关联模块的睡眠回调函数，常用于关闭、待机某模块
7. `new_page()` 新建空白页，当前页面将被隐藏(display属性)，新建的空白页将压入页面管理栈，即是将在页面上显示，返回新建的这个页面。

   返回的这个dom元素对象有自定义成员 `cleanFuncList`，这样管理该页面的模块可以向其中push一个清理函数，执行`pop_page`时将执行 `cleanFuncList` 里所有的函数再弹出页面。

8. `pop_page(num)`：从页面管理栈里弹出 num 个对象，页面将显示弹出后栈指针指向的页面。返回实际弹出的页面数量。

### 关于页面管理栈：

页面管理栈是前端用来管理页面树的结构，它决定当前显示哪个页面。只有栈指针指向的页面会被显示，其他页面均隐藏(display属性)。页面管理栈里默认且最少有一个页面，即是这个布局模块的根页面，就是前端打开未加载任何功能模块时显示的那个页面，其无法被弹出。

## 功能模块：

### 功能模块的前端部分

功能模块的前端部分应当设计为方便装卸的形式，在`<head>`里加上`<script>`标签引用它的js文件(例如example.js)，无需其他操作就可以实现其功能。

前端部分的第一行应该是定义该功能模块使用的区域索引的变量定义，例如 example.js的第一行： `const EXAMPLE_JS_MODULE_INDEX = 2` 表示example.js将使用frame.js给出的索引为2的区域来绘制它自己的界面。这个变量可以根据用户的需要更改。

另外，`MainUI.html` 在加载所有模块(包括布局模块)的代码前会建立`when_connect_func_list`、`when_disconnect_func_list`、`message_proc_func_list`、`binary_message_proc_func_list`、`onload_func_list`这几个函数列表。其中：


1. `message_proc_func_list` 里的函数形如 `function(data)`，`data` 为一JSON实例，是收到的JSON消息。

2. `binary_message_proc_func_list` 里的函数形如 `func(header, payload)`。`header`为一JSON实例，是收到的二进制流的信息头。`payload` 是一 `ArrayBuffer` 实例，是收到的二进制流。

`MainUI.html` 在 `BasicEvent.when_connect()`、`BasicEvent.when_disconnect()`、`messageProc`、`window\.onload` 函数中会遍历对应的函数列表并调用这些函数，因此功能模块如果要在这些时候做些什么就往这些列表里加入自己的函数。

前端部分至少应实现以下逻辑：

1. 初始化：向 `MainUI.html` 中加入所需的`<style>`标签和各种html标签结构，并在获得的区域绘制初始界面
2. 其各种变量、方法、函数的命名既要见名知意又要足够独特以确保不会与其他模块里的变量意外重名。一般使用加上模块名称前缀的方法。

### 功能模块的后端部分:

`back.py` 运行时会读取 `./config/` 目录下的 `module_config.json`，这个配置文件会告诉`back.py` 从什么地方加载哪些模块，然后 `back.py` 加载这些模块。

每一个后端模块实际上是一个类，这个类至少实现以下方法：

- 构造方法：`__init__(self, global_config)`，其中 `global_config` 是全局配置字典，即 `global_config.json` 的内容。
- `(async) when_connect(websocket)`:将在连接成功时调用。
- `(async) when_disconnect(websocket)`:将在断开连接时调用。
- `(async) message_proc(data)`:消息处理函数，接收到消息时调用。

同时这个模块应该包含以下全局函数：

1. `create_module(global_config, back_version)` 形参分别对应全局配置字典和后端版本字符串(这避免一些模块在不适合的后端版本上加载，若版本不匹配返回空值或0)，返回这个后端模块包含的类对象。

2. `settings()` 用于在安装时通过命令行设置模块参数的函数。该函数将在安装时调用，作为安装向导 `install.py` 的一个环节。

后端使用 websocket 发送二进制块应当遵循的二进制结构：

```text
| 4字节魔数 0x48535631 | JSON字符串长度(int32,大端序)|    ......(二进制流的信息头JSON字符串(UTF8))......    |   二进制流 ......
```

## 编写一个模块

### AI用编写功能模块原则(如果使用ai编写一个功能模块可以将其加在提示词前面)

请遵循如下原则：

- 1.如无必要，勿增实体。
- 2.对于这个模块中任何新增的全局类、函数、变量的名称以及出现在html里元素的id、class名，请确保之前有“`<特有名>_`”前缀或者模块名称前缀，以避免在与其他模块同时使用时产生冲突。

### (前端)布局模块中可以使用的接口、预定义全局变量

#### 接口：


1. 向 `when_connect_func_list`、`when_disconnect_func_list`、`message_proc_func_list`、`binary_message_proc_func_list`、`onload_func_list` 这几个函数列表中加入自定义函数

2. `get_version()`:获取UI的版本，检测是否适配 (MainUI.html里定义)

说明：`get_version()` 返回一json对象，形如：

```json
{
	"version_name": "ROLAND",
	"version": "1.0.0" 
};
```

## 回调函数的调用顺序

```text
初始化几个函数列表
		↓
执行 frame.js
		↓
加载各个功能模块
		↓
定义各个基础方法类(BasicEvent)
		↓
定义WebSock相关函数、注册window.onload
		↓
页面加载完成
		↓
按顺序执行onload_func_list里的函数
如果frame.js往onload_func_list里注册过就最先执行frame.js注册的函数
		↓
尝试连接后端
		↓
成功连接后端
		↓
console.log('连接成功');
		↓
遍历执行when_connect_func_list里的函数
		↓
              ......
```

### 收到后端文本消息时

```text
WebSocket.onmessage 调用异步 messageProc(event)
		↓
确认消息不是 ArrayBuffer/Blob 后执行 JSON.parse(event.data)
		↓
如果 command 是 SET_NOWPATH，MainUI.html 先更新根目录输入框
		↓
按当前数组顺序遍历 message_proc_func_list，并把同一个 data 对象传给每个回调
```

当前静态注册的 treemap 消息处理函数通常排在前面；番剧列表、详情页、播放器等组件的 handler 在组件 render() 时动态 push，调用顺序取决于组件创建顺序。各 handler 必须自行检查 command 和 widgetId，只处理属于自己的消息。页面 cleanFuncList 会移除已销毁组件的动态 handler。

### 收到后端二进制消息时

```text
messageProc(event) 检测到 ArrayBuffer 或 Blob
		↓
Blob 先转换为 ArrayBuffer
		↓
检查至少8字节、HSV1魔数(0x48535631)和JSON头长度是否合法
		↓
解析 UTF-8 JSON header，并从剩余字节切出 payload
		↓
按注册顺序遍历 binary_message_proc_func_list，调用 func(header, payload)
```

播放器组件在 render() 时动态注册 binaryMessageHandler，在页面清理时移除。每个处理函数应检查 type、widgetId、streamId 等字段，避免把其他组件或已经取消的旧流数据写入当前播放器。

### WebSocket 断开和自动重连时

WebSocket.onerror 只记录错误并把内部 isConnected 设为 false；真正的断线回调在随后触发的 WebSocket.onclose 中执行。

```text
WebSocket.onclose 被触发
		↓
输出 console.log('连接断开')
		↓
调用 basicEvent.when_disconnect()
		↓
BasicEvent 先禁用并清空根目录输入框、更新“未连接后端”状态
		↓
按注册顺序遍历 when_disconnect_func_list
```

basicEvent.when\_disconnect() 返回后，onclose 再把内部 isConnected 设为 false，并调用 reconnect()。当前重连延迟为1秒；新连接成功后重新执行上面的 when\_connect\_func\_list，但不会重新执行 window\.onload 或 onload\_func\_list。

### 布局区域和页面管理回调

show\_module(index)：仅当 block\_show\_list\[index] 为 false 时调用对应 when\_show\_callback\_list\[index]；成功后标记为已显示。

hide\_module(index)：仅当 block\_show\_list\[index] 为 true 时调用对应 when\_hide\_callback\_list\[index]；成功后标记为已隐藏。

new\_page()：先隐藏当前页面并创建新页面，然后依次调用所有固定区域已有的 when\_hide 回调，把固定区域标记为隐藏。

pop\_page(num)：按出栈顺序处理页面。每个页面先按 cleanFuncList 数组顺序执行清理函数，再移除DOM；回到根页面后依次执行所有固定区域的 when\_show 回调并标记为显示。

### 后端模块回调顺序

backend/back.py 启动时按 backend/config/module\_config.json 中 modules 的书写顺序加载启用的模块，模块实例保存在 module\_manager.modules 中。当前顺序是 treemap，然后 classify\_shower。

建立连接后：先向前端发送 SET\_NOWPATH，再按模块顺序 await module.when\_connect(websocket)。

收到前端JSON消息后：按模块顺序 await module.message\_proc(websocket, data)。前一个模块处理完成后才调用下一个模块。

连接正常关闭、异常中断或 handler 任务取消后：handler 的 finally 按模块顺序 await module.when\_disconnect(websocket)。单个模块清理失败会被记录，但不会阻止其他模块继续清理。

后端服务退出时：main() 的 finally 按模块顺序查找并调用可选的 module.shutdown()，用于回收仍存活的FFmpeg流、数据库连接等服务级资源。
